## 3.2 线性层：仿射变换

PyTorch：

```python
import torch
from torch import nn

linear = nn.Linear(in_features=2, out_features=3)
x = torch.tensor([[1.0, 2.0], [3.0, 4.0]])
y = linear(x)
print(y.shape)
```

数学形式：

```text
y_j = Σ_i x_i W_{j,i} + b_j
y = xWᵀ + b
```

形状：

```text
x: [T, H]
W: [I, H]
b: [I]
y: [T, I]
```

其中 `T` 是 token 数，`H` 是输入宽度，`I` 是输出宽度。

### 固定数值例子

设：

```text
X = [[1, 2],
     [3, 4]]
W = [[ 1,  0],
     [ 0, -1],
     [ 1,  1]]
b = [0.5, 1.0, -0.5]
```

则：

```text
XWᵀ = [[1, -2, 3],
       [3, -4, 7]]
Y   = [[1.5, -1.0, 2.5],
       [3.5, -3.0, 6.5]]
```

参数量：

```text
weights = I × H = 3×2 = 6
bias    = I     = 3
```

若不共享权重，每个 token 都经过同一个仿射变换，但 token 之间没有交互。Transformer 的 Attention 才负责 token 之间的信息交换。

### 为什么只有线性层不够

两个线性层：

```text
y = (xW₁ᵀ + b₁)W₂ᵀ + b₂
  = x(W₁ᵀW₂ᵀ) + (b₁W₂ᵀ + b₂)
```

它们可以合并成一个线性层。任意多层线性层堆叠，表达能力仍等价于一个仿射变换。激活函数引入非线性，才使网络能表示弯折、门控和复杂关系。

## 3.3 激活函数共同的计算特征

本章三个函数都是逐元素映射：

```text
output.shape == input.shape
output[i,j] = g(input[i,j])
```

因此 `[32, 3072]` 输入产生 `[32, 3072]` 输出。它们不混合不同 feature，也不混合不同 token。

这一点直接决定了融合：

```text
elementwise(x): [T, I]
elementwise ∘ elementwise: 可以按同一索引逐元素计算
```

## 3.4 ReLU

公式：

```text
ReLU(x) = max(0, x)
```

导数：

```text
ReLU'(x) = 1, x > 0
           0, x < 0
           在 0 处没有唯一导数，框架通常取 0
```

固定数值：

| x | -2 | -1 | 0 | 1 | 2 |
|---:|---:|---:|---:|---:|---:|
| ReLU(x) | 0 | 0 | 0 | 1 | 2 |

特点：

- 负数区域梯度为 0，可能出现“死亡 ReLU”；
- 计算只需比较和选择，通常便宜；
- 输出可能有很多 0；
- Transformer 常用 GELU 或 SiLU，而不是 ReLU。

## 3.5 GELU

精确形式：

```text
GELU(x) = x × Φ(x)
```

其中 `Φ(x)` 是标准正态分布的累积分布函数：

```text
Φ(x) = 0.5 × (1 + erf(x / √2))
```

所以：

```text
GELU(x) = 0.5x(1 + erf(x/√2))
```

导数：

```text
GELU'(x) = Φ(x) + x φ(x)
φ(x) = exp(-x²/2) / √(2π)
```

常用近似：

```text
GELU_tanh(x) ≈ 0.5x
               × (1 + tanh(
                   √(2/π)(x + 0.044715x³)
                 ))
```

固定数值：

| x | -2 | -1 | 0 | 1 | 2 |
|---:|---:|---:|---:|---:|---:|
| GELU(x) | -0.045500 | -0.158655 | 0 | 0.841345 | 1.954500 |
| GELU'(x) | -0.085232 | -0.083315 | 0.5 | 1.083315 | 1.085232 |

注意 GELU 不是简单的截断：`-2` 仍得到一个小负数。这与 ReLU 的硬零不同。

### 计算成本直觉

精确 GELU 含 `erf`、平方、开方常量、乘加。近似版用 `tanh` 和三次项。哪个更快取决于 dtype、数学指令、Kernel 实现和硬件，不能只数公式里的符号。

真正可以确定的是：

- 所有逐元素激活都必须读写激活张量；
- 中间 Tensor 越多，HBM 往返越多；
- 对 Decode 的小张量，Kernel launch 可能与数学运算同样重要；
- 对较大 Prefill，访存和函数指令会共同影响。

## 3.6 SiLU 与 Sigmoid

Sigmoid：

```text
σ(x) = 1 / (1 + exp(-x))
```

SiLU（也叫 Swish）：

```text
SiLU(x) = xσ(x)
```

导数：

```text
SiLU'(x) = σ(x) + xσ(x)(1 - σ(x))
          = σ(x)(1 + x(1 - σ(x)))
```

固定数值：

| x | -2 | -1 | 0 | 1 | 2 |
|---:|---:|---:|---:|---:|---:|
| SiLU(x) | -0.238406 | -0.268941 | 0 | 0.731059 | 1.761594 |
| SiLU'(x) | -0.090784 | 0.072329 | 0.5 | 0.927671 | 1.090784 |

SiLU 在负数区不是全零，而是平滑地压到接近 0。它允许少量负值通过，但权重衰减。

### 数值稳定性

直接写：

```python
1 / (1 + torch.exp(-x))
```

当 `x` 很负时，`exp(-x)` 可能溢出。PyTorch 的 `torch.sigmoid` 会实现更稳的数值形式。教学时手写公式是为了理解，工程中优先使用框架稳定实现。

## 3.7 固定数值实验

```python
import torch
import torch.nn.functional as F

x = torch.tensor([-2., -1., 0., 1., 2.])
print(F.relu(x))
print(F.gelu(x))
print(F.silu(x))
```

预期：

```text
ReLU: tensor([0., 0., 0., 1., 2.])
GELU: tensor([-0.0455, -0.1587,  0.0000,  0.8413,  1.9545])
SiLU: tensor([-0.2384, -0.2689,  0.0000,  0.7311,  1.7616])
```

计算梯度：

```python
x = torch.tensor([-2., -1., 0., 1., 2.], requires_grad=True)
y = F.silu(x)
y.sum().backward()
print(x.grad)
```

预期：

```text
tensor([-0.0908,  0.0723,  0.5000,  0.9277,  1.0908])
```

这里的上游梯度是每个元素 1。若上游是 `[0.5, 2, ...]`，则逐元素相乘。

## 3.8 形状不会变，但 dtype 和精度可能变

```python
x = torch.randn(4, 8, dtype=torch.bfloat16)
for fn in (F.relu, F.gelu, F.silu):
    y = fn(x)
    print(fn.__name__, x.shape, y.shape, y.dtype)
```

通常会得到相同的 `[4,8]` 和 BF16。某些实现可能内部提升到 FP32 计算再写回，这就是“计算精度”和“存储 dtype”不是同一件事。

例如 nano-vLLM 的 RMSNorm 会临时使用 float：

```text
BF16 输入 -> FP32 计算平方和与 rsqrt -> 转回 BF16 -> 乘权重
```

这增加少量转换，但避免在低精度中做敏感归约。

## 3.9 激活函数和 Qwen3 的具体选择

普通 FFN 常见形式：

```text
h = GELU(xW₁ᵀ + b₁)
y = hW₂ᵀ + b₂
```

Qwen3 使用 SwiGLU 风格的门控 FFN：

```text
gate = xW_gateᵀ
up   = xW_upᵀ
h    = SiLU(gate) × up
y    = hW_downᵀ
```

因此 `hidden_act="silu"` 不是“把整个 MLP 的线性输出直接做一次 SiLU”，而是和 `up` 分支逐元素相乘，形成门控。

下一章会详细推导形状、参数和 nano-vLLM 的权重合并方式。

## 3.10 计算开销如何比较才公平

不要只写：

```text
ReLU 比 GELU 快，因为公式短
```

应至少记录：

- Tensor 形状和 dtype；
- 输入是否在 GPU 缓存中；
- Eager、`torch.compile` 还是自定义 Kernel；
- warmup 与重复次数；
- 纯激活的时间，还是包含层前后 GEMM 的端到端时间；
- 是否正确；
- 峰值显存。

示例实验：

```python
from labs.common import benchmark_cuda

for fn in (torch.relu, torch.nn.functional.gelu, torch.nn.functional.silu):
    ms = benchmark_cuda(lambda: fn(x), warmup=20, repeats=100)
    bytes_read = x.numel() * x.element_size()
    bytes_write = bytes_read
    effective_bw = (bytes_read + bytes_write) / (ms * 1e-3) / 1e9
    print(fn.__name__, f"{ms:.4f} ms", f"{effective_bw:.1f} GB/s")
```

即使 ReLU 的数学更简单，小 Tensor 也可能被 launch 固定成本主导。大 Tensor 更容易接近带宽上限。

## 3.11 常见错误

| 错误 | 现象 | 修正 |
|---|---|---|
| 对整段 hidden 做 softmax | 归一化跨 hidden 维，语义错误 | softmax 常用于 logits 选择维，不替代逐元素激活 |
| 把 GELU 写成 `max(0,x)` | 负数行为不同 | 用 `F.gelu` 作参考 |
| 手写 sigmoid 造成 overflow | `inf`/`nan` | 用 `torch.sigmoid` |
| 忽略激活内部 FP32 提升 | 性能账与 dtype 假设不符 | 查实现、做 profiler |
| 用 `clamp_min(0)` 替代 ReLU 梯度验证 | 在 0 点语义可能不同 | 明确边界规则 |
| 反复 `contiguous()` | 额外复制激活 | 用 profiler 检查 |

## 3.14 与 nano-vLLM 的关联

Qwen3 的 `Qwen3MLP` 使用 `SiluAndMul`，即 `SiLU(gate) * up`。nano-vLLM 为它单独写了一个 `@torch.compile` 的 `nn.Module`，正是为了让激活和门控乘法有机会落在少数融合 Kernel 中。本章的 SiLU 数学、形状和局部梯度，是理解下一步“为什么需要融合”的直接入口。
