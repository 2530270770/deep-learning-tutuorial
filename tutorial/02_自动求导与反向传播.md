# 第 2 章 自动求导与反向传播

## 2.1 本章目标与前置知识

推理引擎主要运行前向计算，但读 PyTorch 源码、做自定义算子时仍必须理解自动求导：

- 知道 PyTorch 为什么能自动算出梯度；
- 能从链式法则手推一个标量网络；
- 能说明 `loss.backward()` 累积了什么；
- 能区分 `requires_grad`、`detach`、`no_grad`、`inference_mode`；
- 能看懂线性层和激活函数的局部梯度形状；
- 会用 `gradcheck` 验证自己的 backward。

前置知识只有导数、链式法则和矩阵形状。可以先不追求微积分技巧，重点是把每一步看成“上游标量灵敏度 × 本地导数”。

运行：

```bash

```

## 2.2 前向计算图

以单变量为例：

```text
x = 2
w = 3
b = -1
z = w*x + b = 5
y = z² = 25
```

设损失为 `L = y`。反向时从输出往输入问同一个问题：

> 如果我给这个中间量加一点点，最终损失会变化多少？

这正好是导数：

```text
dL/dy = 1
dy/dz = 2z = 10
dL/dz = 10
dz/dw = x = 2
dz/db = 1
dz/dx = w = 3
```

继续用链式法则：

```text
dL/dw = dL/dz × dz/dw = 10 × 2 = 20
dL/db = 10 × 1 = 10
dL/dx = 10 × 3 = 30
```

PyTorch 不是“推导出符号表达式再执行”，而是在前向时构建计算图，在 backward 时按拓扑逆序调用每个算子的反向规则。

## 2.3 自动求导的最小代码

```python
import torch

x = torch.tensor(2.0, requires_grad=True)
w = torch.tensor(3.0, requires_grad=True)
b = torch.tensor(-1.0, requires_grad=True)

z = w * x + b
y = z.square()
y.backward()

print("z =", z.item())
print("y =", y.item())
print("dw =", w.grad.item())
print("db =", b.grad.item())
print("dx =", x.grad.item())
```

预期输出：

```text
z = 5.0
y = 25.0
dw = 20.0
db = 10.0
dx = 30.0
```

`y.backward()` 要求 `y` 是标量或传入与输出同形状的 `gradient`。若 `y` 是向量，默认不允许直接 backward，因为“向量的导数”需要一个上游权重来说明每个输出如何影响最终目标。

## 2.4 标量损失的完整训练环

```python
model = torch.nn.Linear(3, 1)
opt = torch.optim.SGD(model.parameters(), lr=0.1)

x = torch.randn(8, 3)
target = torch.randn(8, 1)

pred = model(x)
loss = ((pred - target) ** 2).mean()

opt.zero_grad(set_to_none=True)
loss.backward()
opt.step()
```

四步的意义：

1. `zero_grad`：清除上一步留下的梯度；
2. `forward`：建立计算图；
3. `backward`：从 loss 逆序计算并累加梯度；
4. `step`：优化器按梯度更新参数。

在推理中通常没有这四步，只有 `with torch.inference_mode(): model(...)`。

## 2.5 线性层反向的公式与形状

线性层：

```text
Y = XWᵀ + b
X: [T, H]
W: [I, H]
Y: [T, I]
b: [I]
```

设最终损失为标量 `L`，反向传入：

```text
dL/dY: [T, I]
```

参数的梯度：

```text
dL/dW = (dL/dY)ᵀ @ X          # [I, T] @ [T, H] = [I, H]
dL/db = sum over T of dL/dY   # [I]
dL/dX = dL/dY @ W             # [T, I] @ [I, H] = [T, H]
```

这三条是阅读推理 Kernel 反向实现的基础。即使推理只需要前向，若做训练加速、LoRA 或自定义 autograd Function，也会再次遇到它们。

### 形状检查

```python
X = torch.randn(T, H)
W = torch.randn(I, H)
b = torch.randn(I)

Y = X @ W.T + b
dY = torch.randn_like(Y)

dW = dY.T @ X
db = dY.sum(dim=0)
dX = dY @ W

print(Y.shape, dW.shape, db.shape, dX.shape)
```

预期：

```text
torch.Size([T, I]) torch.Size([I, H]) torch.Size([I]) torch.Size([T, H])
```

## 2.6 激活函数的局部梯度

逐元素激活不改变形状。若：

```text
y_i = g(x_i)
```

则：

```text
dL/dx_i = dL/dy_i × g'(x_i)
```

于是激活 backward 的核心就是“上游梯度 × 本地导数”，形状仍为 `[T, I]`。

以 SiLU 为例：

```text
SiLU(x) = xσ(x)
σ(x) = 1 / (1 + exp(-x))
SiLU'(x) = σ(x) × (1 + x(1 - σ(x)))
```

当 `x=1` 时：

```text
σ(1) ≈ 0.731059
SiLU(1) ≈ 0.731059
SiLU'(1) ≈ 0.927671
```

所以若上游梯度 `dL/dy=2`，则：

```text
dL/dx ≈ 2 × 0.927671 = 1.855342
```

## 2.7 梯度累积、清零和冻结

PyTorch 的 `.grad` 默认是累加的：

```python
loss1.backward(retain_graph=True)
loss2.backward()
```

两次 backward 会叠加到同一个参数梯度。训练循环通常每步清零。梯度累积则故意跨多个小 batch 累加，再统一更新。

推理时不要调用 backward；使用：

```python
with torch.inference_mode():
    output = model(input_ids)
```

`torch.no_grad()` 也关闭计算图，`inference_mode()` 更进一步，禁止会与推理优化冲突的部分版本计数和 autograd 元数据。对纯推理优先前者。

### 常见错误

- 忘记清零 gradient，导致梯度越来越大；
- 已有非标量输出的 loss 没写清；
- 为节省显存对仍需参与反向的激活调用 `detach`；
- 在 inference 代码里保留巨大中间图的引用，使本应释放的显存没释放；
- 对小数值梯度只在 FP16 上比较，误差淹没问题。

## 2.8 detach 与原地操作

```python
x = torch.tensor([1.0, 2.0], requires_grad=True)
y = x * 2
z = y.detach() * 3
```

`z` 通过乘法连接到 `y.detach()`，但不会把梯度传回 `x`。`detach` 不是“只读”，它只是把当前张量从计算图中截断，仍可继续参与前向。

原地操作：

```python
x = torch.ones(2, requires_grad=True)
y = x * 2
y.add_(1)       # 某些情况下可能破坏 autograd 所需版本
```

PyTorch 会通过 version counter 检测部分原地修改。推理中原地操作很常见，因为不需要保存反向信息；训练实现则需要特别小心。

## 2.9 gradcheck：验证自己写的 backward

`gradcheck` 用有限差分比较解析梯度：

```python
fn = lambda x: torch.nn.functional.silu(x).sum()
x = torch.randn(5, dtype=torch.double, requires_grad=True)
assert torch.autograd.gradcheck(fn, (x,), eps=1e-6, atol=1e-4)
```

建议：

- 使用 float64；
- 输入点避开不可导点，例如 ReLU 的 0；
- 对 F.linear、SiLU、GELU 都做一次；
- 先用 PyTorch reference 验证数值，再做低精度 Kernel 的性能测试。

对于没有 backward 的自定义推理算子，不能直接 gradcheck；若只服务于 inference，应改用 forward 数值参考和边界测试。

## 2.10 通过线性层和 SiLU 理解局部视角

两层 toy 网络：

```text
x: [8, 4]
W1: [7, 4] -> a: [8, 7]
g = SiLU(a)
W2: [2, 7] -> logits: [8, 2]
loss = MSE(logits, target)
```

反向传播时：

```text
dL/dlogits: [8, 2]
dW2:        [2, 7]
dL/dg:      [8, 7]
dL/da:      [8, 7]
dW1:        [7, 4]
dL/dx:      [8, 4]
```

关键不是背维度，而是知道每个量“到底对哪个输出负责”。阅读源码时，只要沿着 shape 和“哪个参数收到梯度”这两条线，复杂网络会变成一组重复的小问题。

## 2.14 与 nano-vLLM 的关联

nano-vLLM 的生成路径在 `torch.inference_mode()` 中运行，不需要保存反向图，这是它能把激活内存主要留给 KV Cache 和当前 forward 的原因。与此同时，源码中的采样、温度缩放和自定义 Kernel 仍然遵循同样的“上游梯度/上游值 × 本地计算”思想；将来为算子提供 autograd、做 LoRA 或训练验证时，本章的线性层反向与 SiLU 局部导数会直接复用。
